Slide 1 · Multimodal evidence agent

Every Week 2 agent rubric, in one line each.

Core requirements on the left, the polish that landed since Thursday on the right — both halves are graded, both are shipped.

Core agent rubric

1
Document ingestion & extraction 3 doc types

A separate ingestion graph rasterises uploads, runs a vision LLM against a strict Zod schema with per-field page+bbox+quote, matches demographics, and persists to extraction_artifacts at pending confirmation — chart never auto-modified.

2
Hybrid RAG with rerank

108 USPSTF recommendations chunked deterministically, indexed dense+BM25 in one Pinecone serverless index, fused to top-20 then Cohere-reranked to top-3 — only top-3 reaches the synthesizer.

3
Supervisor + workers, inspectable

LangGraph supervisor chooses from a closed enum of handoffs (chart re-fetch, document evidence, guideline evidence, kickoff extraction, synthesize) with required rationale, capped iterations, and full LangSmith trace per decision.

4
Citation contract & verifier

One {source_type, source_id, page_or_section, field_or_chunk_id, quote_or_value} shape across chart / extracted_document / guideline; the verifier resolves every claim against its indexed source set, drops anything it can't anchor, no fallback path.

5
Eval-driven CI gate per-category

50-case golden set with boolean rubrics (schema_valid, citation_present, factually_consistent, safe_refusal, no_phi_in_logs) — each category now fails independently instead of one bundled 5% gate, so a single rubric regression actually blocks the merge.

6
Observability + cost/latency

Every encounter emits tool sequence, per-step latency, token usage, cost estimate, retrieval hits, extraction confidence, and eval outcome to LangSmith — with PHI scrubbed at every boundary (see right column).

Sharpened since Thursday

A
Query rewriting + RRF fusion retrieval

The evidence retriever now generates multiple paraphrased queries, runs each against the hybrid index, and fuses results with reciprocal-rank fusion — wider candidate pool reaches the reranker, sharper top-3 reaches the synthesizer.

B
Third doc type: DOCX referrals

Referral DOCX joins lab PDF and intake form on the same strict-schema → page+bbox citation path; the agent can also retrieve documents that were never uploaded through the chat panel.

C
In-chat metric trend charts

The synthesizer renders trends for any cited numeric Observation series inline in the answer, so "is her A1c trending up?" gets a chart anchored to the same chart citations as the prose.

D
PHI-safe logging, end to end

Patched the nodes that were emitting un-scrubbed inputs/outputs to LangSmith; production now defaults to inputs/outputs off, with redaction enforced on the paths still permitted to log.

E
Per-rubric eval gate

Replaced the single 5%-bundle threshold with per-category pass thresholds — citation_present regressing alone now blocks the merge instead of being averaged away.

Slide 2 · Surprise challenge

Patient dashboard ported, not redesigned — and shipped alongside the legacy one.

React 19 + Vite + TanStack Router on the OpenEMR FHIR API, mounted as a second entry point so the legacy dashboard keeps working untouched.

Required parity, on FHIR

1
OAuth2 / OIDC sign-in

SPA authenticates via the existing OpenEMR OAuth2 server using fhirclient; legacy session cookies remain the fallback for pages still rendered server-side.

2
Persistent patient header

Name, DOB, sex, MRN, and active status pulled live from Patient — the React shell renders the header once and routes both native cards and iframed legacy pages underneath it.

3
Five FHIR-backed clinical cards

Allergies, Problem List, Medications, Prescriptions, and Care Team each consume the live FHIR resources directly; loading and empty states are first-class, not afterthoughts.

4
+1 chosen section: Clinical Co-Pilot tab

The new dashboard hosts a full clone of the Co-Pilot panel as its extra section, so the agent ships into the modernised UI from day one rather than waiting for a follow-on cutover.

The architectural bet

Two entry points, one EHR

Entry point A Legacy PHP dashboard
  • Untouched server-rendered pages
  • Same auth, same session, same workflow
  • Available to every clinician on day one
Entry point B · new React SPA on FHIR
  • Top-level + patient-level nav as React
  • Native cards via FHIR + OAuth2
  • Co-Pilot tab embedded natively
Bridge: sub-nav pages not yet rebuilt render in iframes inside the SPA shell, talking to the host through shims that mirror legacy top.restoreSession(), patient-switch, and navigation events — gradual section-by-section rebuild, full workflow available from either entry point.
React 19 + Vite Fast HMR, modern hooks, small build surface.
TanStack Router Type-safe routes for the new top-level shell.
fhirclient + Medplum types Standards-based FHIR access against the existing API.
Closing · Why these specific changes

What landed in the last 72 hours, and why each one mattered.

1
Multi-query rewriting + RRF fusion

Single-query retrieval was missing relevant USPSTF recommendations on paraphrased asks; fanning out paraphrases and fusing by reciprocal rank gives the reranker a stronger candidate pool, which directly lifts citation_present and factually_consistent on the eval suite.

2
DOCX referrals + retrieval of pre-existing docs

Real charts have referrals scanned in months ago, not just today's chat upload — adding DOCX as a third strict-schema doc type and indexing the existing artifact set lets the agent pull from documents that were never dragged onto the panel.

3
In-chat metric trend charts

Trends are how clinicians actually read labs; the synthesizer now renders a chart for any cited numeric Observation series inline, anchored to the same chart citations as the prose around it.

4
PHI scrubbing patched + LangSmith I/O off in prod

Audit found a handful of nodes still emitting un-redacted inputs/outputs to LangSmith — patched, and production now defaults to inputs/outputs disabled, with the no_phi_in_logs rubric expanded to cover them.

5
Per-category eval gate

A single bundled 5% threshold could mask a citation regression behind a refusal improvement; the gate is now per-rubric, so each category fails on its own merits and the grading drill stops the relevant one cold.

6
Dashboard V2 as a coexisting entry point

Cutover-style dashboard rebuilds break clinics on day one; running the React SPA alongside the legacy dashboard with iframed bridges and a one-click toggle lets us beta-test in production without forcing reorientation.

Final note from the spec: "The best submissions will feel narrower than the original spec and stronger because of it." Every change above tightened a real edge — retrieval recall, document coverage, log safety, eval signal, rollout risk — without expanding scope.
