Slide 1 — the new agent graph

LLM Supervisor, Model-Driven Retrievers, Deterministic Safety

The supervisor is an LLM call, not a rule set. Each iteration the model picks one handoff from a closed enumeration and supplies a required rationale. Retriever calls after the first chart fetch are model-driven — the agent decides which tools to call. Determinism is preserved only where it's load-bearing for safety: the verifier, the hard stops, and the ingestion pipeline.

Why LLM-driven, not rule-based

Non-determinism is the lesson the W2 assignment is testing. Rule-based routing is defensible but doesn't exercise the agentic-system skill. LLM routing constrained by a closed-enum tool surface, structured-output coercion, and a required rationale per decision is materially stronger inspectability — the model is explaining itself, and the explanation is logged.

How the supervisor stays inspectable

Closed enumeration of handoffs (model cannot invent actions). Required rationale field (Zod-enforced, non-empty). Iteration cap of 10 with cap-hit forced synthesize. Every iteration logs to LangSmith with state observed, chosen handoff, rationale, args, and token usage. The full decision chain per turn is reconstructable post-hoc.

Why two graphs, not one

Producer-shaped work (extraction) and consumer-shaped work (answering) have different latency, failure, and cost profiles. Forcing them into one runtime collides their concerns. The same pipeline runs whether triggered by a panel upload, a front-desk autosweep listener, or a CLI replay.

Slide 2 — multimodal ingestion

Pipeline Plus Tiered Persistence

One pipeline. Three invokers. Idempotent on (document_hash, extractor_version). Three persistence tiers separate "the source document" from "facts that are clinically promoted."

Step 1 rasterize

PDF bytes → page PNGs uploaded to DO Spaces transient prefix with a single-call signed URL.

Step 2 vision

Claude Sonnet 4.x with strict schema. Per-field bbox + page + quote + self-reported confidence.

Step 3 schemaValidate

Zod with .passthrough(). Drops unknown fields; rejects missing required.

Step 4 patientMatch

Compare extracted demographics against chart. Refuse on mismatch — wrong-patient document is a hard fail.

Step 5 persist

Write Tier-1 DocumentReference + Tier-2 extraction_artifacts row at pending_confirmation.

Step 6 emitDeltas

Diff extracted facts against chart state. Surface deltas for the UI to flag.

Three invokers, one pipeline

Conversational supervisor Path A — manual upload during a conversation. Supervisor's kickoffExtraction handoff awaits the pipeline; progress streams over SSE.
OpenEMR upload event Path B — front-desk autosweep. DocumentUploadedEvent listener invokes the same pipeline with a system-actor JWT. Phase-2 delivery.
CLI replay Debug, regression reproduction, eval re-runs. Same code path. Idempotency key prevents duplicate work.

Tier 1 — source document

Always lands in OpenEMR (no clinical risk). DocumentReference uuid + bytes in DO Spaces under a per-patient prefix. Categorized so it shows up in OpenEMR's existing document UI.

Tier 2 — extraction artifacts

Land in agent Postgres at pending_confirmation. Strict-schema JSON with bboxes. Cited by the synthesizer with source_type='extracted_document'. Never auto-written to the chart.

Tier 3 — chart records

Land in OpenEMR only on explicit clinician acceptance. Inline accept/reject in the briefing. On accept: FHIR resources written via the new ObservationLabWriteService (labs) or lists/family_history rows (intake), each carrying source_document_uuid.

Why Spaces signed URLs, not inline base64

Avoids ~4/3× request inflation. ≤5-min TTL, single-call signing. Transient prefix has a 24h lifecycle policy. The trade — Anthropic must reach the URL for the call's duration — is bounded by the short TTL and the bucket's egress posture.

Why a confirmation gate, not auto-write

Wrong-extraction-into-the-chart is a real harm scenario. The gate keeps the canonical record clean by default. The MVP demo shows the gate working — clinician reviews and accepts — which is a stronger story than silent automated writes.

Slide 3 — hybrid RAG & the citation contract

One Citation Shape, Three Source Types

Every retriever produces the same SourceReference shape. The verifier indexes all three source types uniformly. The renderer's chip-click behavior dispatches on source_type — bbox overlay, section snippet, or chart record link.

Unified SourceReference (Q6 / Q10)

source_type: 'chart' | 'extracted_document' | 'guideline'
source_id:   "obs-uuid-…"     // FHIR uuid / artifact id / chunk id
locator: {
  page?:    1,           // extracted_document only
  bbox?:    [120,340,80,24], // extracted_document only
  section?: "ADA-2024 §6.5",  // guideline only
  field?:   "observation.value"
},
quote:      "7.8",
confidence?: 0.97,         // vision-extracted only
meta?: { … }                // per-source debug data

W1's SourceReference renames into this shape in one coordinated PHP/TS migration. The contract test ensures both sides drift together or fail together.

RAG stack

Sequence after MVP: ADA → ACC/AHA HTN → AGS Beers → CDC vaccines, then stop and review evals. One source at a time, eval-validated between each.

Three source types — three click-through behaviors

chart FHIR resource uuid. Click → OpenEMR record page. W1 carry-forward, unchanged.
extracted_document Artifact uuid + page + bbox. Click → side-by-side PDF.js pane, multi-page pre-scrolled, bbox highlighted.
guideline Corpus chunk id + section. Click → popover with chunk text, publication, year, link out.

Why one shape over three

The verifier resolves every claim against source_id against an indexed source set — same accept-or-reject boundary regardless of type. The renderer dispatches on source_type for chip behavior. A discriminated union of three shapes would force a switch on every verification path. One shape keeps both layers symmetric.

Why hybrid + rerank, not dense alone

Clinical guidelines have both narrative ("aspirin therapy is recommended for…") and hard tabular markers (LOINC codes, drug names, dose ranges). Dense retrieval handles the first; sparse handles the second. Rerank corrects the noise from each leg before the top-3 reaches the synthesizer.

Slide 4 — eval gate

50 Cases, Real Model, Boolean Rubrics

The PDF's hard gate: graders will inject a regression and confirm CI fails. Our gate runs every PR against the real model — vision, embeddings, rerank, synthesizer — across 50 cases shaped by capability under test.

Real model in CI — the whole stack

All 50 cases run against the real vision LLM, real supervisor LLM (every iteration), real embeddings, real Cohere rerank. Non-determinism is the thing being tested; the gate validates the whole non-deterministic chain works under variance.

Cost per PR

~50 cases × ~$0.05–0.08 (vision + supervisor iterations dominate) = ~$2.50–4.00/PR. CI hard cap at $5 prevents runaway loops. Latency 3–5 minutes parallelized — inside the merge-gate window.

Rubrics designed for non-determinism

schema_valid and citation_present are structural — survive model variance cleanly. Supervisor-routing rubrics assert plausibility (chosen handoff in case's allowed set) not exact-match. Iteration cap is the deterministic backstop: cap-hit forced synthesize is itself eval-pinned.

Boolean, not LLM-as-judge

The PDF explicitly warns against LLM-as-judge without a clear rubric. Each rubric is a pure function (case, agent_output) → boolean. Failures are actionable; no ambiguity about "the judge said it's a 7."

Fixtures bake into the seeding pipeline

Same archetype + PRNG seed produces a chart and the documents that pair with it. Real public-domain templates filled with archetype-derived data. Hand-authored regression fixtures land alongside per the W1 "every bug becomes a permanent eval case" rule.

Defense summary

Week 2 deliberately feels narrower than the spec. Two graphs, three retriever handoffs, one citation shape, one corpus, one vision model, real-model CI gating 50 cases. Every expansion vector — more doc types, more guideline sources, the critic agent, autosweep — has a slot in the architecture but ships post-MVP under explicit eval-driven discipline. The PDF's load-bearing requirements (multimodal ingest with provenance, evidence grounding, inspectable routing, eval-driven CI) are each satisfied by exactly one architectural mechanism, not three competing ones.
